# 梦想罐 DreamJar 从零搭建教程

照着下面的步骤一步一步做，大约 1–2 小时可以让项目在 GitHub 上线。每一步都写了“怎么确认成功”，卡住时先对照这一行。

---

## 第 1 步：准备账号和软件

### 1.1 注册 GitHub
打开 https://github.com ，点 Sign up 注册。用户名会出现在网址里（`https://用户名.github.io`），建议简短好记。

### 1.2 安装 Node.js
1. 打开 https://nodejs.org ，下载 **LTS（长期支持）版**，一路“下一步”安装。
2. 打开终端（Windows：按 Win 键搜索“PowerShell”；Mac：打开“终端”App），输入：
   ```bash
   node -v
   npm -v
   ```
   **成功标志**：分别显示版本号，比如 `v20.x.x` 和 `10.x.x`。

### 1.3 安装 Git
1. Windows：https://git-scm.com 下载安装，选项全部默认。Mac：终端输入 `git --version`，按提示安装开发者工具。
2. **成功标志**：`git --version` 显示版本号。
3. 设置你的名字和邮箱（用注册 GitHub 的邮箱）：
   ```bash
   git config --global user.name "你的名字"
   git config --global user.email "你的邮箱@example.com"
   ```

### 1.4 安装代码编辑器
推荐 VS Code：https://code.visualstudio.com 。

---

## 第 2 步：在本地跑起来

1. 把下载的 `dreamjar.zip` 解压到一个好找的位置，比如“文档/dreamjar”。
2. 用 VS Code 打开这个文件夹（文件 → 打开文件夹），再打开内置终端（顶部菜单 终端 → 新建终端）。
3. 安装依赖：
   ```bash
   npm install
   ```
   国内下载慢可以先切换镜像再装：
   ```bash
   npm config set registry https://registry.npmmirror.com
   ```
   **成功标志**：文件夹里多出 `node_modules` 和 `package-lock.json`。
4. 启动开发服务器：
   ```bash
   npm run dev
   ```
   **成功标志**：终端显示 `Local: http://localhost:5173/`，浏览器打开这个地址能看到应用。
5. 逐个试一遍：添加愿望、点星标设为目标、写成功日记、录入一笔收入、打开复利计算、在设置里切换语言。
6. 按 `Ctrl + C` 停止服务器。

---

## 第 3 步：改成你自己的项目

需要改的地方：

| 文件 | 改什么 |
|---|---|
| `package.json` | `name` 改成你的项目名（小写英文、可用短横线） |
| `index.html` | `<title>` |
| `src/locales/*.json` | `app.title`、`app.tagline` |
| `README.md`、`README.zh-CN.md` | 把 `YOUR-USERNAME` / `你的用户名` 换成你的 GitHub 用户名；仓库名不叫 dreamjar 的话也一并换掉 |
| `LICENSE` | 第 3 行的版权人可以换成你的名字 |

**版权提醒**：项目名不要用书名，也不要用书中角色的名字；界面和文档里的说明都用自己的话写，不摘录原书。README 里已经写好了“灵感来自……，与作者及出版方无关”的声明，保留即可。

---

## 第 4 步：在 GitHub 上建仓库

1. 登录 GitHub，右上角 **+** → **New repository**。
2. Repository name 填 `dreamjar`（或你改的名字），Description 写一句简介。
3. 选择 **Public**（公开才能免费使用 GitHub Pages）。
4. **不要勾选** “Add a README”“Add .gitignore”“Choose a license”——这些项目里已经有了，勾了会导致第一次推送冲突。
5. 点 **Create repository**，页面会显示仓库地址，形如 `https://github.com/用户名/dreamjar.git`，复制下来。

---

## 第 5 步：把代码推送上去

在项目文件夹的终端里依次执行：

```bash
git init -b main
git add .
git commit -m "Initial commit: DreamJar MVP"
git remote add origin https://github.com/用户名/dreamjar.git
git push -u origin main
```

第一次推送会要求登录：
- **最省事**：弹出浏览器窗口时直接登录授权（Windows 的 Git 自带这个功能）。
- 如果要求输入密码：GitHub 不接受账号密码，需要用“令牌”。打开 GitHub → 右上角头像 → Settings → Developer settings → Personal access tokens → Fine-grained tokens → Generate new token，仓库权限给 **Contents: Read and write**，生成后复制，推送时粘贴到密码处。
- 或者安装 GitHub Desktop，用图形界面完成推送。

**成功标志**：刷新 GitHub 仓库页面，能看到所有文件，README 显示在下方。

---

## 第 6 步：开启 GitHub Pages 自动部署

项目里的 `.github/workflows/deploy.yml` 已经写好了自动部署流程，只需要打开开关：

1. 仓库页面 → **Settings** → 左侧 **Pages**。
2. **Build and deployment** 下的 Source 选 **GitHub Actions**。
3. 回到仓库顶部点 **Actions** 标签，找到 “Deploy to GitHub Pages”。如果还没运行，点进去 → **Run workflow**。
4. 等 1–2 分钟变成绿色对勾。

**成功标志**：打开 `https://用户名.github.io/dreamjar/` 能用。以后每次 `git push` 到 main 都会自动更新网站。

手机上打开这个网址，用浏览器的“添加到主屏幕”，就能像 App 一样使用。

---

## 第 7 步：完善仓库页面

1. 仓库首页右侧 **About** 旁的齿轮：填写简介、网站地址（勾选 “Use your GitHub Pages website”），Topics 加上 `personal-finance`、`pwa`、`i18n`、`react`、`local-first`。
2. Settings → General → Features 里勾选 **Discussions**，方便用户交流。
3. Issue 模板（问题反馈、新增语言）已经在 `.github/ISSUE_TEMPLATE/` 里，推送后自动生效。

---

## 第 8 步：新增一种语言（以法语为例）

1. 复制 `src/locales/en.json`，重命名为 `fr.json`。
2. 只翻译冒号右边的文字，键名和 `{{n}}`、`{{count}}` 等占位符保持原样。
3. 打开 `src/i18n.ts`，改三处：
   ```ts
   import fr from './locales/fr.json';                // ① 引入
   { code: 'fr', label: 'Français' },                 // ② 加到 languages 列表
   fr: { translation: fr },                           // ③ 加到 resources
   ```
4. 需要的话，在 `src/format.ts` 的 `currencies` 里补上对应货币。
5. `npm run dev` 检查一遍，然后：
   ```bash
   git add .
   git commit -m "Add French translation"
   git push
   ```

说明：
- 以 `_one` / `_other` 结尾的键是单复数形式。中文、日文、韩文只需要 `_other`；俄语、阿拉伯语等有更多形式（`_few`、`_many` 等），译者按 i18next 的规则补上即可。
- 阿拉伯语、希伯来语等从右到左的语言，页面方向会自动切换，无需额外处理。

## 第 9 步：让社区帮你翻译（Weblate）

不会用 Git 的人也能参与翻译：

1. 打开 https://hosted.weblate.org ，用 GitHub 账号登录。
2. 申请 **Libre（开源免费）托管**，创建项目，添加组件时填：
   - 源代码仓库：`https://github.com/用户名/dreamjar.git`，分支 `main`
   - 文件格式：**i18next JSON file**
   - 文件掩码：`src/locales/*.json`
   - 单语基础文件：`src/locales/en.json`
3. 按 Weblate 的提示配置推送权限（通常是把它提供的 SSH 公钥加到仓库的 Settings → Deploy keys，并勾选写权限；或安装 Weblate 的 GitHub 集成）。
4. 之后译者在网页上翻译，Weblate 会把译文提交回你的仓库。
5. 把 Weblate 给的“翻译进度徽章”代码贴到 README 顶部。

新增语言后，记得按第 8 步第 3 点在 `i18n.ts` 里登记，否则界面里选不到。

Weblate 的界面和选项可能会更新，以它的官方文档为准。

## 第 10 步：日常开发流程

每做一个新功能：

```bash
git checkout -b feature/功能名      # 新建分支
# ……修改代码，npm run dev 测试……
npm run typecheck                    # 检查类型错误
npm run build                        # 确认能打包
git add .
git commit -m "描述你做了什么"
git push -u origin feature/功能名
```

然后到 GitHub 页面点 **Compare & pull request**，检查后合并到 main，网站自动更新。

---

## 第 11 步：发布版本

1. 修改 `package.json` 里的 `version`（如 `0.2.0`），提交。
2. 打标签并推送：
   ```bash
   git tag v0.2.0
   git push --tags
   ```
3. 仓库页面右侧 **Releases** → **Draft a new release**，选刚才的标签，写更新说明（新增了什么、修复了什么），发布。

---

## 第 12 步：后续可以加的功能

按书中的实践顺序，可以逐步加入：
- **赚钱点子板**：记录“我能帮别人解决什么问题”，以及每个点子的尝试结果。
- **目标储蓄联动**：收入分罐中的“目标”部分，直接分配到具体目标上。
- **金鹅账户增长图**：结合复利计算，显示按当前储蓄速度多少年后能达到某个数。
- **每日提醒**：写成功日记的提醒（需要加 Service Worker 做 PWA 离线和通知）。
- **更多语言**：繁体中文、韩语、西班牙语、法语。

每个新功能都开一个 Issue 写清楚需求，标上 `good first issue` 的简单任务最容易吸引新贡献者。

## 常见问题

**打开网站是空白页**
按 F12 看控制台。最常见的原因是 `vite.config.ts` 里的 `base` 被改掉了，保持 `'./'` 即可。

**`git push` 被拒绝（rejected）**
通常是建仓库时勾选了 README 导致远程有本地没有的提交。执行：
```bash
git pull origin main --allow-unrelated-histories
git push
```

**Actions 显示红叉**
点进失败的任务看日志，大多是代码有错误。先在本地运行 `npm run build`，修好再推送。

**换了电脑，数据不见了**
数据只存在原来那台设备的浏览器里。在旧设备“设置 → 导出备份”，到新设备“导入备份”。

**`npm install` 报错或很慢**
确认 Node 是 LTS 版本；国内网络按第 2 步切换镜像。
